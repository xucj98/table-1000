# 可拆装笔帽的物理方案选型

## 最终设计：原生钢珠弹簧卡扣

采用 PhysX 原生接触与关节表达保持机构：笔颈有一圈凸棱，笔帽内有三颗钢珠；每颗钢珠通过径向滑动关节连接帽壳，关节的弹簧驱动将球压向笔颈。拔出和压入时，凸棱推动钢珠向外移动，越过凸棱后弹簧使钢珠回位。

每支笔包含笔身、帽壳和三颗钢珠，共五个物理刚体。保持与脱离由接触和弹簧共同求解，不需要脚本识别配对、施加笔帽保持力、吸附或解除连接。兼容笔帽可直接交换，重力、夹持和其他物体的接触自然参与同一物理求解。视觉上仍表现为笔身和笔帽两个组件，内部钢珠可只用于碰撞。

这是用于装配任务的等效卡扣机构，不是对真实笔帽塑料过盈和形变的精确复原。研究参数中半径 0.8 mm 的球质量为 1 g，属于工程代理；质量、摩擦与弹簧均未实物标定。参数及几何分别由资产的 `physics.py`、`object.py` 维护，经统一入口生成 USD 资产。

### 选择依据与验收边界

研究已实现弱拉保持、强拉拔出、重复盖合、两帽互换，以及紧帽保持、未越过卡扣的松帽在翻转后滑落。相比自行计算保持力或维护额外连接插件，这种实现的资产分发和维护更简单。

正式验收围绕四个典型过程：紧松两帽对比拔出并放稳、轻推停在卡扣前再加力盖紧、三高度同时跌落、紧松两帽从竖直朝上旋转至朝下。以视频为主，辅以力与位置曲线及 RTF；实验诊断不扩充为长期测试清单。

4 ms 高速冲击出现瞬态穿透并不单独构成拒收条件，需观察是否稳定恢复、是否持续穿地或异常飞散。研究中 1 m 跌落的最大地面穿透在 4/2 ms 下约为 18.4/9.6 mm，卡扣是否越棱也随步长变化。因此本方案用于低速装配与宏观跌落演示，不能预测真实脱帽高度或准确冲击载荷。

## 其他尝试与结论

| 思路 | 实现与发现 | 结论 |
| --- | --- | --- |
| 脚本等效保持力 | 根据相对位置和速度计算轴向保持力，在每个物理步施加。可以完成拔插，但对自由运动的预测需正确计入重力、夹具及接触影响，曾出现漏计重力的问题。 | 不作为正式保持机制，避免不断补充外力来源和状态规则。 |
| 原生柔顺接触与径向弹性预压 | 通过接触柔顺性或径向弹性自由度产生预压力，再由接触摩擦保持。部分原型能弱拉保持，但出现重插卡滞、预压丢失或明显步长敏感性。 | 原理可用，但当时原型不适合直接采用；不能据此否定所有原生接触方案。最终钢珠卡扣使用明确凸棱和径向弹簧，形成更清楚的装配阻力。 |
| 限力驱动和可分离约束 | 用约束限制横向运动，轴向限力驱动保持，脚本负责捕获和解除。可完成部分交换，但位置驱动包含回座趋势，不等同静摩擦，曾在重插过座时解除。 | 未选用；仍需额外配对与解除逻辑，且已测试版本存在重插问题。 |
| 官方 Surface Gripper / Robot Assembler | 提供抓取连接或固定关节装配工具。抓取断裂参数与总轴向保持力并非简单对应，连接期间的碰撞过滤也不直接适合笔帽止点。 | 适合各自的抓取或装配用途，不能直接当作笔帽摩擦模型。 |
| Factory / IndustReal 与 RoboDojo 装配任务 | 复现了 Factory 插销和螺母任务成功；RoboDojo 中可见真实螺纹碰撞及插接资产。但插入成功判据不等同撤去夹具后保持、抗拔和反复拆装均已验证。 | 可参考资产、控制与任务组织，未找到能直接替代本项目笔帽保持机构的已验证入口。 |
| 柔性与压力接触 | 调研了 Isaac 柔性体及其他压力接触方法。测试版本存在静摩擦、运行环境或计算成本限制；外部后端原型中的夹具误差也不能归罪于接触模型。 | 未选用；项目要求 Isaac，当前需求不必扩展到完整材料形变求解。 |
| BrickSim 连接与承载 QP | 识别装配接口后吸附对齐并建立固定约束，通过动量与约束反力估算外载，再用 QP 判定连接断裂。修复两项松弛阶段容差设置后，原积木 4/2 ms 测试中的求解失败与迟到断裂消失；笔帽适配实现了拔插和真实互换。 | 具有有效装配能力，但笔帽松放时会落座自动连接，连接锁定旋转并有吸附与速度清零。还需维护原生插件及版本相关接口，故未选作正式方案。 |

上述结论针对实际测试的版本和原型，不是对这些方法普遍能力的否定。BrickSim 笔帽翻转还出现少量初始化阶段无法完全表示的载荷分量，未宣称任意混合载荷均已验证。

## 成本与取舍

在 Isaac Sim 5.1、CPU PhysX、TGS 32/8、4 ms、单笔活动拆装的研究测量中，原生钢珠方案无渲染端到端 RTF 约 1.92，BrickSim 约 2.04；双笔约 1.29/1.23。两者处于同一量级。模型质量、碰撞配置和共享机器负载不同，不能据这些数字严格排名；正式资产按最终实现重新报告运行条件和 RTF。

选择钢珠方案主要基于所需行为、原生资产表达与维护成本，而非少量性能差异。研究代码和临时环境不作为长期依赖；正式实现与操作步骤以[资产生产规范](asset-pipeline/README.md)和[第二章教程](../tutorials/02-physics-assets.md)为准。
