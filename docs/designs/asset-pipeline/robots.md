# 机器人资产规范

规定从厂商 URDF 包得到仿真用机器人的文件、几何、碰撞、物理、控制接口与验收要求。交付物包括可以导入仿真器的模型，规划器、控制接口（关节控制和末端位姿控制），并在仿真中验证行为和性能。以 [X1Pro](../../../asset_sources/robots/x1pro/) 为例；执行命令见[第三章](../../tutorials/03-robot-import.md)。

**适用范围**：带平行两指夹爪手臂的机器人，从固定底座的单臂（如装在台座上的 Franka）到带升降、头部和移动底盘的双臂机器人（如 X1Pro）。升降、头部、移动底盘都是可选部件。腿式机器人（如机械狗）不在范围内：转换、构建、环境与后端接口可以复用，机器人描述、控制器和验收用例需另行设计。

## 流程与存储

```text
厂商 URDF 包（assets/robots/<name>/raw/，存档于 Hugging Face 数据集）
    ──prepare.py 的选择 + 转换工具──> robot.urdf + meshes/visual/ + meshes/collision/
                                     └──检查──> check.json
robot.urdf (+ 虚拟底盘关节) + physics.py ──导入与物理层──> import/robot.usd + robot.usda
robot.urdf ──Blender──> three_quarter.jpg
robot.py (SPEC) ──> 运动学与规划模型、控制器 ──robot_test.py 的检查场景──> report.json
```

| 位置 | 内容 | Git |
| --- | --- | --- |
| `asset_sources/robots/<name>/` | `robot.urdf`、`meshes/visual/`、`meshes/collision/`、`prepare.py`（转换选择）、`physics.py`（物理层）、`robot.py`（机器人描述 `SPEC`）、`robot_test.py`（验收设置）、`README.md`、`three_quarter.jpg` | 是 |
| `table_1000/robots/` | 与具体机器人无关的工具：描述类型（`spec.py`）、转换、构建、预览、运动学与规划（`kinematics.py`、`planning_model.py`）、控制器（`controllers.py`）、验收用例库（`checks.py`）、遥控（`teleop.py`） | 是 |
| `scripts/robots/` | `prepare_robot.py`、`build_robot.py`、`check_robot.py`、`teleop.py` | 是 |
| `tests/robots/` | 通用代码的单元测试（测试内生成的固定底座单臂）；`test_robot_sources.py` 对每台机器人检查描述、关键姿态、IK 与验收设置 | 是 |
| `assets/robots/<name>/raw/` | 厂商原始包，原样保存 | 否；存档于数据集，版本记录在 `assets.lock.json` |
| `assets/robots/<name>/` 其余 | `import/`、`robot.usda`、源码快照、`build.json`、`prepare.json`、`check.json` | 否；可由源码重建 |

使用机器人只需 Git 中的源码：构建、源码检查（`--check`）、验收和遥控都不读取原始包，场景、任务和其他资产的开发者不需要数据集权限。只有重新生成源码（改 `prepare.py` 的选择或转换工具、厂商数据更新）才需要原始包。

源码目录不超过 10 MB，不依赖上游 ROS 包即可构建：URDF 只用相对路径，不用 `package://`。README 写明原始包名称、所选 URDF 配置和对厂商数据的全部改动。

**增加一台机器人**：在 `asset_sources/robots/<name>/` 下写 `prepare.py` 并生成 `robot.urdf` 与网格，写 `physics.py`、`robot.py`、`robot_test.py` 和 README；通用代码不需要改动。与物体资产把各自的 `physics_test.py` 放在资产目录下一样，每台机器人的验收设置放在它自己的 `robot_test.py` 里，用例和指标在 `table_1000/robots/checks.py` 中统一实现。

## 运动学与刚体

- 关节名、类型、限位、质量与惯量保持厂商值；改动集中在 `prepare.py` 的 `edit(root)`，并在 README 中逐条列出（例如 mimic 改为独立驱动、电机关节改为固定、限位调整）。
- 固定关节连接的零件并入所属运动刚体，质量与惯量按平行轴定理合并；合并后的连杆保留为固定在刚体上的空坐标系，TCP、相机等位置由它们的固定关节偏移给出。Isaac 导入器只合并无质量连杆，不能代替这一步。
- README 写明刚体数；构建后核对。

## 外观

- 每个外观网格以二次误差简化，面数从总预算按 √(原面数) 分配起步，不满足误差就加倍：简化前后表面距离（双向采样）的 99 分位不超过 **1 mm**。
- 只按面数预算简化会压坏薄壳：X1Pro 躯干在 2.7 万面时误差约 19 mm。
- 外观网格存为 PLY，删除厂商用作占位的 1 mm 方块。

## 碰撞

- 只用凸块。每个外观网格用 CoACD（阈值 0.3）分为 1–4 块，块数在 `prepare.py` 的 `PIECES` 中按连杆给出；传感器、轮子等用一个凸包。凸块按质心排序后写出，使结果不随 CoACD 线程调度变化。
- 外观顶点须在碰撞凸块内，越出不超过 **0.5 mm**；由检查工具测量并写入 `check.json`。
- 厂商 URDF 自带的碰撞网格是非凸网格，不直接使用。
- 包在其他刚体内部、不会接触外界的连杆（如夹爪座内的电机）不设碰撞，列在 `NO_COLLISION`。

## 物理

`physics.py` 的 `author(import_path, output_path)` 在导入结果上写 `robot.usda`，只包含：

| 内容 | 要求 |
| --- | --- |
| 关节驱动 | 刚度、阻尼按弧度或米给出，转换到 USD 的角度单位；力与速度上限取 URDF |
| 求解 | articulation 位置/速度迭代次数 |
| 自碰撞与过滤 | 开启自碰撞；`FilteredPairsAPI` 只排除真机上不会接触、凸块却重叠的刚体对，逐对注明原因（如两指、嵌在躯干上的头部外壳、零位折叠时靠在上臂上的前臂）；规划模型的 SRDF 排除同样的对 |
| 材料 | 机身与夹爪指垫的静/动摩擦 |
| 重力补偿 | 如采用理想重力补偿（连杆不受重力），在 README 中写明；手中物体仍受重力 |
| 夹爪 | 真机由一个电机同步驱动两指时，用 `PhysxMimicJointAPI` 耦合两指，只驱动一指。两指各自驱动、都顶在力上限时，沿开合方向没有回复力，手一加速，两指连同物体一起侧移 |
| 指垫 | 扭转摩擦半径（`torsionalPatchRadius`）。点接触没有扭转摩擦，物体会绕两指连线转动 |
| 底盘 | 移动底盘由构建时加入的三个虚拟关节（世界 x、y、偏航）驱动，推力和扭矩上限取轮电机能给出的值，挡住时停下而不硬推；机器人与地面的碰撞关闭，轮子只随动 |

未对照真机标定的数值在文件和 README 中注明“仿真取值，未标定”。

## 机器人层：运动学、规划与控制

结构参照 ManiSkill3 的 agent 与 controller，与仿真器无关，同一套代码可接不同后端。

- **描述**：`robot.py` 的 `SPEC`（`RobotSpec`）列出各手臂（关节、TCP、手指、开合换算、安装连杆；第一只为主手臂），可选的升降、头部、移动底盘（虚拟关节、轮子、速度、加速度、推力上限），关键姿态与相机。零位（全部关节为 0）总是关键姿态之一，X1Pro 的零位也是真机最常用的起始姿态（躯干最低、两臂折叠、头平视）。有移动底盘时，底盘位姿即虚拟关节值，机器人 prim 留在原点；没有时，机器人 prim 放在场景给定的位姿（可带高度，如台座）。
- **运动学与规划**（`RobotModel`）：一个 MPlib/Pinocchio 模型包含全部身体关节，每只手臂一个规划器，升降保持不动。手臂规划同时检查躯干、头和另一只手臂当前的位置。提供正运动学、IK、头部朝向（look-at）、RRTConnect 与直线（screw）规划、路径碰撞检查。规划世界默认只有机器人本身（自碰撞），任务按需加入物体。
- **控制**（`RobotController`）：25 Hz 一个动作，每个动作覆盖 10 个 4 ms 物理步。位置目标在物理步间线性插值，并给出对应速度作前馈。

| 动作组 | 内容 | 模式 |
| --- | --- | --- |
| `base` | 前进速度、偏航角速度 | 速度（限速、限加速度、防积分饱和） |
| `lift`、`head` | 关节位置 | 绝对或增量 |
| `<arm>` | 6 个关节位置，或 TCP 位姿增量（安装连杆坐标系，内部 IK） | `pos`、`delta`、`ee_delta` |
| `<arm>_gripper` | 两指间距 | 绝对 |

**环境**（`table_1000/sim/env.py` 的 `Env`）把控制器接到仿真后端：`reset(layout)` 写入物体摆放与机器人关节（不重建舞台），`step(action)` 执行一个控制周期，返回全部关节位置与速度、底盘位姿、各手臂 TCP 位姿和时间。仿真器相关的调用只在后端里，所有数组带环境维 N。目前只有 Isaac Sim CPU 后端（`table_1000/sim/isaac/backend.py`，N = 1）。`table_1000/sim/isaac/` 也放 Isaac 的公共工具：启动（Kit 设置只在本次运行生效）、物理世界、舞台写入、相机与渲染设置，物体资产的物理测试同样使用它们；以后增加的后端并列放在 `table_1000/sim/<后端>/`。GPU 并行后端（Isaac Lab）待实现，多环境下的批量行为尚未验证。

## 验收

分两部分。资产检查与物理常识用例是硬性条件；对比指标只记录，用于比较不同碰撞方案、参数或机器人。

**资产检查**

| 项目 | 通过条件 |
| --- | --- |
| 源码检查 `check.json` | 外观越出碰撞凸块不超过 0.5 mm；目录不超过 10 MB |
| 转换报告 `prepare.json` | 每个外观网格误差不超过 1 mm；刚体数与 README 一致 |
| 构建 | 刚体数、碰撞形状数与 README 一致 |
| 缩略图 | 左为外观，右为按刚体分色的碰撞凸块；人工确认外观无破面、碰撞覆盖完整、刚体划分合理 |

**物理常识用例**（`scripts/robots/check_robot.py`，检查场景：机器人前方一张桌子与若干简单形状）

| 用例 | 符合常识的表现 |
| --- | --- |
| 关键姿态 | 零位、`ready` 等每个关键姿态：规划模型中没有碰撞对；仿真中静置 1 s，机器人各刚体之间无接触，关节漂移不超过 0.01 rad |
| 手臂撞固定块 | 被挡住，不穿透、不抖动（去趋势后的标准差不超过 1 mrad）；撤掉方块后到达目标 |
| 手臂推自由物 | 方块、圆柱被推动，仍在桌上 |
| 物体落到机身上 | 停在可见表面上（与外观网格的距离不超过 15 mm）或滚落 |
| 躯干升入隔板 | 被挡住，不发散，随后能下降 |
| 自碰撞 | 手臂撞到躯干时停下，能退回 |
| 夹持与晃动 | 方块、圆柱、细棒夹起后晃动手腕，相对 TCP 漂移不超过 5 mm，松开后落下 |
| 底盘撞墙 | 停下、不推动墙，能开走 |
| 持物行驶 | 前进、急停、原地转，手中物体漂移不超过 5 mm |
| 关节限位 | 超限指令停在限位，不越界、不抖动 |

用例在 `table_1000/robots/checks.py`，由每台机器人的 `robot_test.py` 设置：检查场景的桌子（`TABLE`）、机器人摆放与起始关键姿态（`ROBOT`）、桌面上主手臂前方的工作点（`WORK`，各用例的目标位姿相对它和桌面高度给出）、物体下落的目标连杆（`DROP_LINKS`）和要运行的用例（`CASES`，默认是全部适用的用例）。需要某个部件的用例只适用于有该部件的机器人：躯干升入隔板需要升降，底盘撞墙与持物行驶需要移动底盘；没有升降和头部时，关节限位用例检查主手臂。

每个用例都检查：机器人接触的穿透不超过 2 mm（物体下落撞击时不超过 10 mm：4 ms 步长下，高速运动中的轻微穿透可以接受）；关节速度不超过 URDF 上限的 1.5 倍；物体速度不超过 2 m/s。用例全部记录进 `report.json`，并可录视频复核。

**对比指标**：模型与仿真的 TCP 一致性；IK 成功率、精度、耗时；只考虑自碰撞的随机起止规划的成功率和耗时；关节轨迹跟踪误差与到位时间；底盘速度跟踪、原地转向漂移、停车误差；静止与运动时每物理步耗时。碰撞方案（凸块块数、顶点上限、盒子与圆柱）对精度与耗时的影响见[研究记录](https://github.com/xucj98/table-1000/blob/7660d8c0c0763cee752152c25ddbbc255aef495a/docs/research/robot-collision.md)（ref `refs/research/robot-collision`）：碰撞形状几乎不影响仿真耗时，规划耗时取决于自碰撞检查的连杆对数。

**遥控**：`scripts/robots/teleop.py` 在浏览器中用键盘操作机器人，供人工验收和测试，会话动作可回放。

修改 `prepare.py` 的选择、转换工具或 `physics.py` 后，重新生成或构建并逐项重验；碰撞凸块或物理参数变化后，依赖它的场景任务需重新批量验收。
