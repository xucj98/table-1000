# 开发约定

## 仓库职责

`table-1000` 保存本项目的代码、研究文档、操作手册和资产定义。RoboDojo 等外部仿真框架在各自仓库维护；本项目的使用说明必须注明命令在哪个仓库执行。

对象与场景按 [资产存储布局](designs/storage-layout.md) 保存。外部框架下载的资产与权重遵循其自身约定，不与本项目资产混放。

## 提交与审查

`tests/` 以单元测试为主，子目录与 `table_1000/` 的源码目录对应，例如 `table_1000/modeling/` 对应 `tests/modeling/`，测试文件使用 `test_*.py` 命名。需要 Blender 或生成资产的集成测试应明确注明运行环境与输入；测试产物写入 `outputs/`，不存入 `tests/`。

从最新 `main` 创建开发分支，通过 PR 提交。每个 PR 聚焦一个可独立审查的改动，说明问题、最终行为、验证结果和已知限制。

合并前完成代码审查；操作手册还需按文档命令复现，并检查生成结果。修正后重新验证受影响的部分。使用 squash 合并，使 `main` 每个提交对应一个完整的 PR。

Review 以正常使用流程能正确运行、结果可信和代码简洁为准，不为假设的边界情况增加防御性检查、异常兜底或测试。底层操作能直接报错时不重复提前检查，测试只覆盖关键行为和已复现的实际问题。

## 公开内容与本地内容

可复用代码、公共使用说明、设计文档和资产生成源码、配置进入仓库。公共文档面向任意读者，使用仓库相对路径或明确的路径参数，不依赖特定机器、内部任务记录或私有部署。

凭据、环境目录、内部服务器地址、个人部署记录和临时调试文件不提交。生成或下载的资产写入已忽略的 `assets/`，日志、测试结果等写入已忽略的 `outputs/`；本地说明可放在已忽略的 `.local/`。
